# Astra 档位与协作

## 能力来源与实际运行

2026-09-07（Asia/Shanghai）已通过 OpenAI Docs 连接器搜索并读取 [Astra API 模型页](https://developers.openai.com/api/docs/models/gpt-6-astra)和[客户端模型说明](https://learn.chatgpt.com/docs/models)。来源、原句、定位、文本哈希及获取方式见 [sources.json](sources.json) 的 `OPENAI-ASTRA-API` 与 `OPENAI-CODEX-MODES`。这是版本相关信息，迁移环境时重新核对。

- API 模型页列出 `reasoning.effort = low / medium / high / xhigh / max`。不要将客户端的 `ultra` 直接写进 API 请求。
- 官方客户端说明中，Max 给选定模型更多推理时间，Ultra 使用子代理并行处理可拆分任务。可用选项受账号、登录方式、客户端及发布范围影响；文档列出能力不代表本账号已经开通。
- 先读取宿主提供的模型目录、模型菜单或会话元数据。区分 `requested`（计划）、`supported`（当前宿主公布能力）和 `observed`（本次实际可观测记录）。提示词、输出长度、速度及命令示例都不能证明本次用了某档位。
- 未观察到的实际模型、档位或上游提供方填 `UNVERIFIED`。自定义提供方显示模型名只记录为该接口报告值，不认证其内部模型或计算预算。

## 按角色制定策略

[model-policy.json](model-policy.json) 是可复制到项目的策略与记录示例，声明执行、关键设计、独立审查三种角色。它不会被 `run_workflow.py` 读取，不是模型调度器，也不会自动改动客户端或用户全局设置。`preferred_*` 和 `fallback_effort_order` 仅表达工作流建议，不是宿主支持列表，更不是已执行记录。

| 角色 | 本工作流的默认偏好 | 产出与退出条件 |
| --- | --- | --- |
| 执行 `execution` | `gpt-6-astra` / Max | 提取、清洗、实现、计算、图表、保义改写；阶段验收产物齐备即前进 |
| 关键设计 `critical_design` | `gpt-6-astra` / Ultra，适用于有独立子任务的关键问题 | 目标函数或假设比较、可核验推导、参数辨识与误差分析；形成推荐和验证协议即转入执行 |
| 独立审查 `independent_review` | `gpt-6-astra` / Ultra，按证据任务分工 | 以原始需求和结果重新核对边界、守恒、可行性及冲突结论；交付问题清单、反例和关闭证据 |

这些是任务策略，未做 Max 与 Ultra 对建模效果的比较实验。简单任务可沿用当前已验证设置；核心决策和正式结论仍须满足相同验收要求。独立审查指独立核验路径：两个代理复述同一结果不是独立计算。子代理不可用时，按明确次序执行另一个数学方法或检查程序，并记录没有并行审查。

## 不可用时的回退

1. 保留用户明确指定的模型。对每次任务先确认运行界面是客户端还是直接 API，并查询当次可用档位；不拿仓库旧表当现行能力表。
2. Ultra 不受支持、不可用或任务不适合拆分时，优先用该模型已确认可用的 Max。Max 也不可用时，按 `xhigh / high / medium / low` 顺序选择当前支持的首项，记录原因与实际值。直接 Astra API 只从其已确认支持的档位选择，关键设计和审查可使用 Max 并顺序执行检查。
3. 宿主无法暴露档位或实际设置时，保持当前会话，不注入猜测的参数；记录 `UNVERIFIED`，继续文件检查、计算和已授权任务。不能报告“已切换 Ultra”。
4. 指定模型不可用时，不自动换成未获授权的新模型。已有替代模型授权则核对替代模型自身支持项并记录；没有替代授权时暂停依赖新模型调用的部分，继续本地计算、证据整理等独立工作。如用户把某模型或档位设为硬性验收条件，回退结果明确不满足该条件。
5. 回退不是降低验收条件。出现反例、无法验证的核心推导或结果冲突时，保留问题状态、可交付基线和人工决策项，不能把较低档位运行成功写成审查完成。

每条记录至少包含任务 ID、角色、时间、界面与提供方、客户端版本（可得时）、计划模型和档位、可用能力来源、实际观测值、回退原因及结果证据。分别记录 AI 检查与队员人工检查。

## 任务级配置示例

下面命令在当前客户端已确认支持时启动新会话；`-c` 是本次命令的配置覆盖，不写全局默认：

```bash
codex -C <项目目录> -m gpt-6-astra -c 'model_reasoning_effort="max"'
```

仅在客户端已确认支持 Ultra 时，将该次启动参数改为 `ultra`。交互式 CLI 可用 `/model` 选择模型及档位；模型目录显示支持和实际运行成功分别留证。仓库不会替用户开启隐藏选项或修改全局配置。策略文件中的示例记录保持 `NOT_RUN`，由实际执行者填写。

开始前按剩余时间给深审明确预算，例如先用剩余研究预算的 5% 做路线审查，保留至少一个能交付的基线。这是可调整起点，不写死比赛时长。关键决策已形成、证据不足需采集或时间盒耗尽时退出深审；无新证据不要为提升模拟分数反复审查。

保持主代理负责需求、决策与整合，将可独立的检索、实现、图形检查交给代理。每个代理交付文件、页码或命令证据；不能并行编辑同一文件。上下文较长时更新状态和续接记录，保留决策、源文件哈希、代码版本、失败分支及真实运行句柄。恢复时先查句柄和结果；观测超时本身不意味着进程失败。
