# Astra 档位与协作

## 三种证据分开

- 官方 API 的 `gpt-6-astra` 模型页列出 `reasoning.effort = low / medium / high / xhigh / max`，不要将 Codex 的 `ultra` 直接写进 API 请求。
- Codex 客户端的 `model_reasoning_effort` 可有不同档位。先查本机模型目录、CLI 帮助与可用接口；列出支持档位只证明客户端公布了能力，不证明本次推理调用完成。
- 在每次运行元数据记录实际传入模型、档位、时间、工具结果与任务 ID。无法读取宿主当前配置时填 `UNVERIFIED`，不根据提示词、速度或回答长度猜测。

官方入口：[Astra 模型页](https://developers.openai.com/api/docs/models/gpt-6-astra)、[Astra 提示指南](https://developers.openai.com/api/docs/guides/latest-model)、[Codex 子代理与档位](https://learn.chatgpt.com/docs/agent-configuration/subagents)。这是版本相关信息，移植环境时重新查询。

## 本工作流的建议策略

以下是任务调度建议，尚不是 Max 与 Ultra 科学效果差异的实验结论。

| 情况 | 建议档位 | 产出与退出条件 |
| --- | --- | --- |
| 资料提取、清洗、基线实现、常规图表与保义改写 | Max | 当前阶段验收产物齐备即前进 |
| 存在多个合理目标函数或假设会改变结论 | Ultra | 比较表、可核验推导、推荐与待队内决策项 |
| 求解成功但违反边界、守恒或独立对拍 | Ultra | 定位最小反例及根因；修复后返回 Max 实现 |
| 难以辨识的参数、离散与连续误差、复杂几何 | Ultra | 识别条件、误差来源及可执行验证协议 |
| 最终数学审查、冲突结论、核心贡献证据审查 | Ultra | 有证据的问题清单和关闭结果，无问题也记录范围 |

开始前按剩余时间给深审明确预算，例如先用剩余研究预算的 5% 做路线审查，保留至少一个能交付的基线。这是可调整起点，不写死比赛时长。Ultra 在关键决策已形成、发现证据不足而应转入采集、或时间盒耗尽时结束；转回 Max 后执行已确定的计算或修复。无新证据不要为提升模拟分数重启审查。

## 配置示例

在终端启动新会话：`codex -C <项目目录> -m gpt-6-astra -c 'model_reasoning_effort="max"'`。深审改为 `ultra`，前提是当前客户端已确认支持。交互式会话可通过客户端模型菜单选择并查看状态。示例命令不是实际切换证据，不修改用户的全局默认。

保持主代理负责需求、决策与整合，将可独立的检索、实现、图形检查交给代理。交付必须有文件、页码或命令证据。两个代理读同一结果说“正确”不能替代不同数学方法的独立计算。不能并行编辑同一文件；发现共享依赖先串行处理。
