# 最终线性方案核验

在 LP/MILP 方案求解完成，或经过取整、裁剪、阈值化、合并和其他后处理后使用。核验对象是论文表格、执行文件实际采用的变量值。这个标准库脚本不求解模型，也不推断题意；非线性约束、逻辑约束和概率保障另写对应检查，不可删去它们后以线性子模型 PASS 代表完整模型。

先独立核对题面到系数、方向、变量域的映射，再导出模型。若求解与检查共同使用了错误的约束定义，两者一致仍不能排除建模错误。来源学习依据见 [C023 范例卡](exemplars/cards/C023.md)：其中正文约束、实际分段与最终表值的差异提示需要检查最终交付方案；下面的数据为新造合成例，未复现该论文。

## 接口与结果

```sh
python <skill>/scripts/verify_linear_solution.py --model <项目>/practice/<演练>/model.json --solution <项目>/practice/<演练>/solution.json --output <项目>/practice/<演练>/verification.json
```

正式任务使用项目既有结果路径。模型和解只读，报告不能覆盖输入；输出写入失败返回 2。退出码 0 表示记录模型的可行性与目标值一致性通过，1 表示数学检查失败，2 表示数据或配置错误。错误报告会覆盖同路径旧报告，避免遗留 PASS；需比较历史版本时使用不同运行目录。

报告给出各约束、变量上下界、整数/二元域、重算目标值的残差、容差和状态，并记录输入与检查器 SHA-256。`feasible` 和 `objective_consistent` 分开，`optimality` 始终为 `NOT_ASSESSED`，`human_validation` 始终为 `NOT_PERFORMED`。

输入用 JSON 数字；内部使用 80 位十进制精度，运算需舍入时直接报错。报告中的数值以十进制字符串保存，避免输出转成浮点数时损失精度。这样也能识别超过二进制浮点精确整数范围的非整数输入。它验证已给出的十进制数据，不补回原始测量或上游浮点计算损失的精度。

## 模型与最终解

`model.json` 示例：

```json
{
  "version": 1,
  "variables": {
    "x": {"domain": "binary", "lower": 0, "upper": 1},
    "y": {"domain": "binary", "lower": 0, "upper": 1},
    "z": {"domain": "binary", "lower": 0, "upper": 1}
  },
  "constraints": [
    {"id": "coverage", "coefficients": {"x": 2, "y": 3, "z": 4}, "sense": ">=", "rhs": 4}
  ],
  "objective": {"sense": "min", "coefficients": {"x": 1, "y": 1.2, "z": 3}, "constant": 0},
  "tolerances": {"absolute": 1e-9, "relative": 0, "integrality": 1e-9}
}
```

变量域支持 `continuous`、`integer`、`binary`；无上下界用 `null`。二元域还会独立检查距 0 或 1 的距离，不能用宽泛上下界取消二元约束。约束方向支持 `<=`、`>=`、`==`，约束 ID 必须唯一。系数表省略的已声明变量系数为零；未知变量、重复 JSON 键、缺失变量、布尔值、NaN/Infinity 和不支持的字段报错。目标方向支持 `min`、`max`，但不据此验证最优性。

`solution.json` 使用最终输出值和相应目标值，包含全部变量：

```json
{"values": {"x": 1, "y": 1, "z": 0}, "objective": 2.2}
```

本例连续松弛解为 `(0.5, 1, 0)`，费用 1.7；它满足覆盖约束但违反整数域。逐项取整为 `(0, 1, 0)` 后，费用 1.2，覆盖量 3 小于 4；不能只看费用降低。八种二元组合中五种可行，最小费用为 2.2。方案 `(0, 0, 1)` 费用 3，可行性和费用核对均通过，但仍不是最优方案。

## 容差和流程连接

对约束、上下界与目标值，阈值为 `absolute + relative * max(abs(lhs), abs(rhs))`。等式检查绝对残差，不等式只检查违反方向；整数与二元域采用单独的 `integrality` 容差。核验前依据单位、数据精度和算法误差确定容差；异尺度模型先作有依据的单位换算或归一化。这里的 `1e-9` 只用于合成例，不是所有题目的默认标准。脚本不修改变量，也不按容差替用户取整。

与工作流连接时，将模型 JSON 和最终解 JSON 声明为核验阶段输入，将本脚本登记为 `code`，报告声明为输出。论文结果生成阶段依赖该报告，核验退出非零后运行器停止，并将失败报告保留在 `.workflow/stale/`。参见 [运行接口](runtime.md)。

若后处理改变了变量，保存处理前后两份值、处理规则、费用差和约束差，并更新 claims 对最终版本的引用。需要改变目标、约束或容差才能让方案通过时，先返回建模决策，不在绘图或写作阶段修饰数值。
