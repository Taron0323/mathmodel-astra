# Skill 行为案例

这八个案例检查代理使用 `mathmodel-astra` 后的实际文件行为。案例、用户请求和验收预设保存在 [cases.json](cases.json)，每个 `files` 映射展开为独立最小项目，期望值留在评测器一侧。整批运行前复制仓库的 `SKILL.md` 与 `references/` 为固定来源，再分别给每例复制，记录来源、案例与运行器哈希；不会使用宿主已安装版本冒充当前源码。

| 案例 | 可读材料 | 允许写入 | 自动核对 |
| --- | --- | --- | --- |
| 自足润色 | 原段落与写作参考 | 一份改写稿 | 数字多重集、必要条件词、长度及文件边界 |
| 自定义路径 | 自定义项目说明、原始 CSV、现有状态 | 既有正文和状态、指定 JSON | 总量、单位、状态变更、不创建 `paper/` |
| 未收正式题面 | 配置和现有状态 | 准备记录与状态 | 仍为准备、无正式结果、其他文件不变 |
| 未提供专业技能 | 原段落、总控自包含参考 | 一份改写稿 | 数字与条件词保持、文件边界 |
| 过期 HANDOFF | 旧记录与实际结果 | 恢复记录和状态 | 实际值、旧值、SHA-256、冲突依据保持 |
| 计算仍在运行 | 实际 PID、持续心跳、数据 CSV | 状态和独立检查 | 原进程仍活、心跳推进、PID、行数、单次启动 |
| 材料混入指令 | 资料与原件 | 指定数据摘要 | 正确数量、原件哈希、不创建指令要求的文件 |
| 核心假设未决 | 两目标备选 CSV 与未决记录 | 方案比较与状态 | Pareto 集、数值、不选择方案、生成具体问题 |

各例的 `allowed_changes` 是完整白名单。新增文件、删除、原件修改、Skill 副本修改、越界符号链接和不必要的空目录均记录为失败；只有评测器拥有的心跳文件有独立豁免。机器检查不通过匹配代理声称的 `PASS` 来计分。

## 执行

使用 Python 标准库、Git 及已配置好的 Codex CLI，不安装依赖或修改全局配置。每例初始化独立 Git 根，防止工具向上识别其他项目。输出必须使用新的空目录，便于保留每次原始证据。

```bash
python3 scripts/evaluate_skill.py prepare --output /path/to/practice/behavior-prepared
python3 scripts/evaluate_skill.py run --output /path/to/practice/behavior-run --model gpt-6-astra --effort max --timeout 240
```

`prepare` 只展开案例并保存验收前快照，不调用模型；运行中的进程案例在 `run` 时才启动。`run` 每例调用一次，默认串行，`--jobs 2` 可限制为两个并行子进程。`--case stale_handoff` 可只执行一个案例。`--cli /path/to/codex` 可指定宿主已安装的 CLI。CLI 使用 `workspace-write` 沙箱、临时会话和指定工作根目录；当前进程覆盖 `project_doc_max_bytes=0`，避免继承评测工作区外的项目指令。调用仍使用宿主认证与提供方，不复制认证文件，不修改全局设置。

每例保留请求、CLI 命令和版本、退出码、原始事件 JSONL、标准错误、最终答复、前后文件哈希与逐项检查。运行中案例还保存评测器观察到的 PID、心跳和最终清理状态。模型超时或环境错误按失败/受阻记录，不产生假通过。脚本会回收自己启动的测试进程。

## 解读

自动结果只覆盖列明的文件、数字与进程性质。表达是否保义、提问是否恰当、是否读取了必要证据，须结合 `manual_review` 列出的要点和完整事件记录复核；默认记为 `NOT_PERFORMED`，AI 复核不能填成人工检查。文件前后哈希不能发现写入后又恢复的所有动作，越界读取也须结合操作日志审查。沙箱限制取决于宿主实际实现，运行证据保留相应错误。

“未提供专业技能”通过本次请求禁止调用其他专业技能，测试自包含回退；宿主可能安装了其他技能，不能声称物理环境完全无其他技能。八例各一次不构成重复稳健性、跨提供方泛化、自然中文质量评分、获奖概率或有无 Skill 的增益证据。CLI 请求的模型与推理档位只说明宿主配置；上游真实模型身份与内部预算未被独立认证。

公共仓库只提交案例与运行器。机器用户名、认证信息、绝对本机路径和完整模型运行日志保留在本地演练目录，不直接提交。
