## 1. 优先处理的三个实际问题

这里的 P1 表示应优先修复的运行正确性问题，P2 表示有明确价值的后续完善。严重性描述的是可复现影响，不代表所有现有演练结果已经出错。

### R1 · P1：运行中上游依赖变化，仍返回完成

**位置：**[run_workflow.py 第 246 行](https://github.com/Taron0323/mathmodel-astra/blob/1aa6884995d4bbcd1f4d1ad0f374719ebcb6fd75/scripts/run_workflow.py#L246) 只重新核对原始输入；[第 261 行](https://github.com/Taron0323/mathmodel-astra/blob/1aa6884995d4bbcd1f4d1ad0f374719ebcb6fd75/scripts/run_workflow.py#L261) 在流程末尾直接保存 `COMPLETE`。

**复现：**第一阶段写入 `value.txt="original"`，第二阶段以此为输入，但在处理期间把它改为 `"modified"`，然后生成报告。`run` 返回退出码 0 和 `COMPLETE`；紧接着 `status` 显示两个阶段均为 `NEEDS_RUN`，且 `all_current=false`。

**影响：**本次“已完成”状态与实际文件不一致。就地清洗、后处理或运行期间编辑代码，都可能造成类似依赖漂移；运行结束后才调用 `status`，检查晚于完成声明。

**优化：**阶段执行前后比对全部登记输入和代码；发生变化时拒绝把该阶段结果登记为当前有效。整体完成前再核对全部阶段的一致性，保存冲突及受影响范围。

**验收：**新增“下游改写上游输入”和“执行期间登记代码发生变化”两类反例，要求当次运行非零退出，不返回 `COMPLETE`；未变化的正常流程继续复用缓存。

### R2 · P1：超时后可能遗留继续写结果的孙进程

**位置：**[run_workflow.py 第 234 行](https://github.com/Taron0323/mathmodel-astra/blob/1aa6884995d4bbcd1f4d1ad0f374719ebcb6fd75/scripts/run_workflow.py#L234) 的超时处理只等待直接子进程；[第 264 行](https://github.com/Taron0323/mathmodel-astra/blob/1aa6884995d4bbcd1f4d1ad0f374719ebcb6fd75/scripts/run_workflow.py#L264) 的中断处理采用同类逻辑。直接子进程退出后，不再确认整个进程组是否仍有成员。

**复现：**阶段启动一个忽略 `SIGTERM` 的孙进程。超时后，直接子进程退出，运行器返回 `FAILED`、移除锁并清空记录 PID；孙进程仍然存活，随后写入 `result.txt`，内容为 `late result from surviving grandchild`。本次测试进程已清理。

**影响：**失败后可能重新出现输出；立即恢复时，旧计算进程和新运行可能同时写文件。现有单层中断检查没有覆盖这个多层进程边界。

**优化：**保存阶段进程组身份，终止宽限期结束后检查整个进程组；对残留成员升级终止，并在确认清理完成后释放续跑锁。

**验收：**覆盖“父进程响应终止、孙进程忽略终止”的场景。超时和中断返回后，不应残留该阶段工作进程，等待原计划写出时刻后也不得出现新输出；随后恢复不与旧进程并发。

### R3 · P1：同一输出的路径别名可绕过单一生产者检查

**位置：**[run_workflow.py 第 74 行](https://github.com/Taron0323/mathmodel-astra/blob/1aa6884995d4bbcd1f4d1ad0f374719ebcb6fd75/scripts/run_workflow.py#L74) 使用规范化路径判断越界，但第 78 行起仍以原始字符串判断输出唯一性。

**复现：**两个阶段分别登记 `results//value.txt` 和 `results/value.txt`。清单检查通过，第二阶段覆盖第一阶段实际文件。`run` 返回 `COMPLETE/0`；随后 `status` 将第一阶段标为 `NEEDS_RUN`。

**影响：**代码已经设定的“一个输出只能有一个生产者”约束没有覆盖等价路径，依赖图可能与真实文件写入关系不一致。

**优化：**清单入口统一形成规范化工作区相对路径，以规范化路径建立生产者、依赖和输入输出冲突检查；再按支持范围补充符号链接及已有硬链接身份检查。

**验收：**上述双斜杠清单在任何阶段执行前返回 `CONFIGURATION_ERROR`，不生成结果或检查点；合法相对路径和从其他目录启动的既有行为保持可用。

## 2. 整体评价：值得保留，下一步应提高可靠性和实测深度

这个 Skill 已经形成可用的研究工作流程。它最有价值的部分，是把题面要求、数学决策、实际计算与论文结论连接起来，并针对取整不可行、重复观测评估和参数非唯一等具体错误给出工具。

它的成熟度并不均匀：流程组织和证据管理较强，部分专项验证有实质实现，跨题型通用化和真实代理行为评价仍有缺口。当前证据适合支持“值得用于赛前训练和队伍主导的建模辅助”，不能量化为提升多少获奖率或所有题型的正确率。

| 维度 | 当前判断 | 判断依据和仍缺的证据 |
| --- | --- | --- |
| 任务组织 | 较成熟 | 51 行入口、按需参考、单阶段边界、恢复与时间盒；尚缺代理执行这些约定的行为评测 |
| 证据工程 | 较强，已补充运行边界修复 | 输入与代码指纹、传递失效、最终图文版本核对；R1 至 R3 已进入回归 |
| 数学判断准则 | 扎实 | 结构先于算法，区分可行性、最优性、预测与拟合、局部秩与结构唯一性 |
| 可运行题型覆盖 | 不均衡 | 运输链、三个专项和新增 ODE 已有实现；网络与评价主要为准则 |
| 写作与图表 | 规则具体 | 保留条件、指标语义、最终输出精度与图文一致性；缺少成对改写及人工评价集 |
| 安装与跨环境复用 | 可用，仍可简化 | 缺专业 Skill 有参考降级，Linux/macOS CI 已通过；Windows 原生未验，版本回滚说明不足 |
| 科学效果增益 | 尚未量化 | 没有代表性任务的有无 Skill 对照，也没有充分 Max/Ultra 对照 |

不提供一个合成总分，因为“流程设计好”“脚本可运行”“研究结论更准确”需要不同证据，一个分数容易掩盖这些差异。

## 3. 具体优点

### 3.1 入口短，分工边界清楚

[SKILL.md](https://github.com/Taron0323/mathmodel-astra/blob/1aa6884995d4bbcd1f4d1ad0f374719ebcb6fd75/SKILL.md) 只有 51 行，负责范围、路由和推进原则。长规则放在参考文件中，支持按阶段读取；专业 Skill 缺失时有自包含参考，减少了安装整套依赖的要求。

单阶段润色不必启动全流程，核心未决选择需要建议与依据，普通实现可以自主决定。这些规则契合比赛的时间压力，设计上避免把每个小改动都扩展成项目重建。

### 3.2 证据检查已经写进程序

[运行签名](https://github.com/Taron0323/mathmodel-astra/blob/1aa6884995d4bbcd1f4d1ad0f374719ebcb6fd75/scripts/run_workflow.py#L102) 包含输入、登记代码、运行器、环境、命令、输出名及上游签名，复用时还核对实际输出哈希。

[运输验证入口](https://github.com/Taron0323/mathmodel-astra/blob/1aa6884995d4bbcd1f4d1ad0f374719ebcb6fd75/scripts/transport_demo.py#L169) 检查验收项完整性及数值证据。图文生成进一步要求实际图片与当前结果对应，失败重验会撤销旧通过状态。这比单纯写“必须严格验证”更有执行价值。

### 3.3 抓住了数学建模中容易误判的几类问题

- [最终线性方案核验](../references/linear-solutions.md) 复查取整或修复后的实际交付值，并将可行性、目标一致性与未核验最优性分开；实现使用高精度 Decimal 并拒绝不精确运算。
- [预测验证](../references/prediction-validation.md) 先问预测谁、预测何时和届时能获得什么信息，区分记录、个体和时间，提供重复观测合成反例。
- [可辨识性](../references/parameter-identifiability.md) 区分结构唯一性、局部一阶信息和含噪估计精度；给定 Jacobian 的 SVD 诊断不能冒充自动证明参数真实。
- [写作准则](../references/writing.md) 具体到费用降幅与效率、百分比与百分点、显示精度与执行精度等语义差异，能够约束结论夸大。

### 3.4 对来源和能力边界较诚实

论文展示、作者报告、当前分析、计算复现分别记录，五张卡片也保留不宜迁移的做法。正式结果、演练、AI 检查、队员人工审查和实际上传分开，Max/Ultra 分工标为策略而非实验结论。这些约定值得保留。

## 4. 后续优化：每项都给出验收办法

本节保留初次审查提出的完整建议，已落地部分以开头修复表为准。重复行为对照、相关误差传播和历史题复现属于仍可继续推进的范围。

### R4 · P1：增加真正的 Skill 行为评测

**证据与问题：**[CI 第 30 行起](https://github.com/Taron0323/mathmodel-astra/blob/1aa6884995d4bbcd1f4d1ad0f374719ebcb6fd75/.github/workflows/runtime.yml#L30) 主要运行 Python 测试和演练，不能验证代理是否遵守 [SKILL.md 的单阶段、既有目录与材料指令边界](https://github.com/Taron0323/mathmodel-astra/blob/1aa6884995d4bbcd1f4d1ad0f374719ebcb6fd75/SKILL.md#L8)。

**优化方案：**建立固定用户请求与最小项目快照，每例写明允许读取的材料、允许新增或修改的文件、禁止行为和可验收结果。建议第一批覆盖八类：自足段落润色、自定义目录、未收题面的准备、缺少专业技能、过期续接记录、仍运行的计算、外部材料混入命令、核心假设未决。

**验收：**保存真实操作记录，统计范围越界、误覆盖文件、无依据完成声明、不必要重跑和任务完成率。使用相同数据和预算做“无 Skill／有 Skill”配对比较，重复运行并报告波动，再评价模型或档位差异。不能只比较回答长度和文风。

### R5 · P1：先标清题型支持层级，再补数学演练

**证据与问题：**[题型参考第 7 行起](https://github.com/Taron0323/mathmodel-astra/blob/1aa6884995d4bbcd1f4d1ad0f374719ebcb6fd75/references/problem-types.md#L7) 覆盖六类结构，但实际端到端链条主要是固定运输例。预测脚本是固定反例，Jacobian 脚本不执行模型拟合，均不等于对应题型的完整通用实现。

**优化方案：**建立能力矩阵，分别标记方法准则、输入输出协议、可运行演练、独立对拍和公开历史题验证。扩展时，优先增加有解析解的 ODE 或守恒系统，检验步长收敛、边界退化和图文版本；随后增加“预测误差进入优化决策”的联合演练。

**验收：**每项新题型至少包含正确实例和故意失败的反例，采用独立方法对拍。相关重采样使用个体或时间块，验证区间覆盖率或最终决策损失，而非只画误差棒。原参考已有 Bootstrap、白化和误差传播建议，待补的是实现与可验证结果，不是再次写入术语。

### R6 · P2：减少规范与总稿的手工漂移

**证据与问题：**基准版本的 [总稿第 28 行](https://github.com/Taron0323/mathmodel-astra/blob/1aa6884995d4bbcd1f4d1ad0f374719ebcb6fd75/docs/mathmodel-astra-guide.md#L28) 无条件规定 `paper/latex/main.tex`，而技能入口要求沿用任意项目布局。[runtime.md 第 3 行](https://github.com/Taron0323/mathmodel-astra/blob/1aa6884995d4bbcd1f4d1ad0f374719ebcb6fd75/references/runtime.md#L3) 的平台描述仍停留在实际验证仅 macOS，本次已核实该提交的 Linux/macOS CI 全部成功。

**本轮已做：**总稿增加基准提交、整理日期和来源索引，将固定论文路径明确为本工作台约定；区分历史规则记录与本轮核验。这是文档修订，不是脚本功能修复。

**后续方案：**以 `SKILL.md` 和相关参考为规范来源，人类阅读总稿作为带来源标记的导出件。先做源段落映射和链接一致性检查；需要长期维护时再加入确定性生成脚本，避免为一个总稿建立复杂文档框架。

**验收：**自定义目录任务无需迁移；每个规范段有来源，参考变化能提示总稿过期，重复生成相同结果。人类长手册不应整体注入每次代理上下文。

### R7 · P2：把动态规则和模型配置来源做成可核对索引

**证据与问题：**[competition.md 第 7 行](https://github.com/Taron0323/mathmodel-astra/blob/1aa6884995d4bbcd1f4d1ad0f374719ebcb6fd75/references/competition.md#L7) 给出声明位置和支撑材料文件名，但公开入口主要是官网首页；[astra-modes.md 第 5 行起](https://github.com/Taron0323/mathmodel-astra/blob/1aa6884995d4bbcd1f4d1ad0f374719ebcb6fd75/references/astra-modes.md#L5) 列出具体支持项，未在该参考内附查询日期和条款原句定位。

**优化方案：**随包维护轻量来源索引，记录稳定 ID、比赛或产品版本、年份和赛区、准确原始 URL、条款原句、发布日期、访问时间、哈希与核验状态。已有本地官方快照可用于生成索引，公开仓库不必分发私人材料。

**验收：**每条文件名、声明位置、时间窗口或模型支持项都能定位原始来源；年份或环境不符时明确待核验。三个赛区及学校要求各自保留适用范围，登录受限项继续跳过。

### R8 · P2：降低首次使用与跨环境复用成本

**证据与问题：**[README 的安装段](https://github.com/Taron0323/mathmodel-astra/blob/1aa6884995d4bbcd1f4d1ad0f374719ebcb6fd75/README.md#L5) 默认使用已登录 GitHub CLI；`astra-modes.md` 提供 Astra 策略，但缺少不支持推荐档位时的完整回退说明。版本锁定、升级与回滚操作也较简略。

**优化方案：**为公开仓库增加无需登录的标准 Git 安装入口，保留原有安装方式；给出固定提交、检查差异、备份和回滚的最小步骤。将执行、关键设计、独立审查映射到可配置模型与档位，默认仍保留 Astra 策略。

**验收：**干净目录可以从公开仓库安装并运行最小例；已有目录不被覆盖；支持 Astra、缺少 Ultra、无法读取宿主配置三类环境均如实记录并继续允许的任务。Windows 先明确支持范围，再决定是否增加进程管理实现和原生 CI。

### 可随后安排的维护

当前 CI 使用 `actions/checkout@v4`、`actions/setup-python@v5` 和 `actions/upload-artifact@v4`。可按各 Action 的当前发布说明检查维护版本，再运行同一平台矩阵；本轮没有独立复核旧版报告中提到的运行时弃用告警，不把历史提示当作本次日志事实。

自然中文可建立成对改写样本，分别评价数字、条件、单位、引用、失败结果保持和可读性。人工可读性由实际人员评价，机器检查不得代填。此项有价值，但优先级低于已复现的运行错误和代理行为评测。
