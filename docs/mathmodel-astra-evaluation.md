# mathmodel-astra 评价与优化建议

## 已验证的优点

- 证据合同把题面、参数、代码、运行、结果、图表和论文位置连起来，并使用哈希防止旧结果静默复用。
- 图表发布会检查实际图片、绘图代码和数值证据的关联；缺图、替换图或过期验证会阻止报告生成。
- 优化最终方案会重新检查变量域、约束和目标值，避免连续解取整后沿用原最优性结论。
- 预测流程明确记录粒度、个体、时间和特征可用时点；合成反例显示记录随机划分与个体隔离划分回答的是不同问题。
- 参数诊断把结构性非唯一、局部 Jacobian 秩和含噪估计精度分开，已有可运行 SVD 诊断器。
- 题型路由、2025 公开论文提炼、自然中文规范和图表规范已接入同一入口；脚本和跨平台 CI 可运行。

## 当前限制

1. 尚未在真实 2026 题面上完成端到端验证，演练通过不代表正式比赛结果或获奖概率。
2. Max/Ultra 目前是调度策略和客户端配置说明，尚无足够代表性的任务集比较完成率、错误类型和返工次数。
3. 各题型的输入/输出协议还没有完全统一；跨题型复用仍需人工整合。
4. Bootstrap、时间块/组块重采样、相关误差传播和决策稳健性支持偏弱。
5. 三个赛区的实际适用通知、学校要求和正式提交包仍需选择队伍后逐项核验。
6. 安装流程偏个人目录同步，公开仓库版本锁定、升级和回滚命令还不够完整。
7. 去 AI 味主要依靠规则和示例，尚无成对改写集与人工评价基准。
8. GitHub Actions 仍有既有 Node.js 20 弃用提示，应安排主版本升级。

## 优先级路线

- **P0**：维护本总稿和快速开始入口；统一证据合同、阶段输出协议、状态字段和跨题型最小接口。
- **P1**：加入 Bootstrap、时间块和个体组块重采样，登记参数扰动、相关误差和预测到决策的误差传播。
- **P1**：建立 Max/Ultra 任务评测集，记录任务完成率、证据完整性、返工次数、错误类别和人工修复量，不只比较文字风格。
- **P2**：为湖南、江苏、河北增加通知快照、差异检查和正式提交包清单；密码或强制登录页面继续跳过并留痕。
- **P2**：建立自然中文改写前后成对样本，评价事实保持、数字一致、逻辑清晰、冗余和人工可读性。
- **P3**：升级 GitHub Actions 到非弃用主版本，并保留四平台组合的回归覆盖。

评价依据是当前仓库脚本、测试、CI 和公开论文提炼记录；它描述工程能力和证据边界，不把任何内部评分转换成真实竞赛排名或获奖概率。
